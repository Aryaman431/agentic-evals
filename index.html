01 · Evaluation Engine

Chatbot Evaluation

Every agent team eventually asks the same question: did the model actually do the right thing? agentic-evals is a standalone, framework-agnostic scoring engine for LLM and agent outputs, published on PyPI with a full pytest suite under tests/. Its canonical chatbot evaluation is the support-answers suite: a refund-status case that requires tool lookup_refund, forbids delete_order, enforces a tool_call_precision threshold of 1.0 and a 2000 ms latency budget, and scores a reply like "Your refund is on its way!" against a trace span. Suites run through evaluate_suite into a JSON EvaluationReport and pass rate, then GateConfig/evaluate_gate turns that into a release gate that can raise SystemExit in CI.

You'll learn

  • How one refund-status case turns required and forbidden tools, a precision threshold, and a latency budget into a pass/fail result
  • When to use deterministic text scorers, trace-aware tool checks, JSON-Schema contracts, or LLM-judge rubrics — and what the three built-in packs cover
  • How a JSON EvaluationReport and pass rate become a release gate, and how agentic-evals run discovers eval files and collapses them into one CI exit code

Frontend: Chatbot-eval/index.html — opens standalone; the Evaluation API needs python Chatbot-eval/server.py (port 8001).

02 · Voice Agents

Voice Agent Evaluation

Voice agents fail in ways text demos never reveal. This use case builds a simulated voice customer-support agent — deterministic intent detection, order-ID extraction, tool selection, response — then evaluates it against the ten-case dataset in dataset.py: STT basics and accents, intents for status, cancel, and refund, tool selection and arguments, task completion, missing-order (ask for the order ID, never guess), and unknown-intent (decline without calling a tool). run_evals.py converts these into an agentic-evals TestSuite and prints a scorecard — 10/10 PASS — with a FastAPI Evaluation API behind an in-dashboard Scenario Lab and fault-injection catalog. render.yaml targets a hosted deployment; STT is simulated and latency is local.

You'll learn

  • The eight evaluation rules that judge a voice-support agent, from transcript accuracy to groundedness
  • How fault injection — wrong tool, corrupted arguments, hallucinated claims, slow reply — proves each evaluator actually catches its fault
  • Which reported numbers are trustworthy: pass rates are real, but STT is simulated and local latency is not production latency

Frontend: voice-agent-evals/index.html — opens standalone; live eval calls need python voice-agent-evals/server.py (port 8001).

03 · Production to Release

From Production Trace to Release Decision

Shipping an agent change on gut feel is a liability. This console walks a financial-assistant production trace — an unusual expense of about $2,847 — through five stages: production trace, AI Ops Spec export, baseline evaluation, simulated replay, and release decision. Verdicts of READY, NOT READY, or NEEDS REVIEW are computed in real code from documented thresholds: an overall delta of at least +2.0, worst-metric regression no worse than −3.0, post-replay safety of at least 80, and post-replay overall of at least 78. Capture, spec, evaluation, and replay are marked simulated; Supabase persistence and API operations are genuinely functional when configured.

You'll learn

  • The five stages: production trace, AI Ops Spec export, baseline evaluation, simulated replay, release decision
  • How documented thresholds turn metric deltas into READY, NOT READY, or NEEDS REVIEW
  • How to compare a prompt, model, or coordination change against a saved baseline through replay

Frontend: Production trace to release decision/index.html — fully self-contained (simulated data). Optional backend: app.py with Supabase when configured.
