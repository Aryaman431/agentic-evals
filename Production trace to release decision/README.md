# Production Trace → Release Decision

A single-service developer observability console that turns a captured production AI workflow into a reusable test scenario — inspect the production trace, export an AI Ops Spec, run a baseline evaluation, simulate a change via replay, and reach a data-driven release decision.

> **SIMULATED DEMO DATA** — AgenticLens production capture is simulated. The AI Ops Spec is a representative example, not an actual AgenticLens export. Evaluation scores are illustrative, generated by built-in demo logic (no real evaluation framework). Replay is simulated — no real agent application is rerun. The backend serves hardcoded sample data: scenarios, runs, and decisions are seeded at startup and every API operation genuinely mutates the in-process store.

## What it does

1. **Production Trace** — timeline of a financial-assistant workflow explaining an unusual expense.
2. **AI Ops Spec** — syntax-coloured JSON spec with copy/save.
3. **Baseline Evaluation** — six deterministic metric scorecards + issue list.
4. **Simulated Replay** — choose prompt/model/coordination change, compare vs baseline.
5. **Release Decision** — READY / NOT READY / NEEDS REVIEW from documented thresholds.

## Architecture

Flat single-service layout — no build step, no microservices, no database:

| File | Purpose |
| --- | --- |
| `app.py` | FastAPI app, API endpoints, in-memory store, static serving |
| `sample_data.py` | **Hardcoded sample records** (scenarios, trace events, runs, decisions) |
| `index.html` | Complete interactive frontend |
| `requirements.txt` | Python dependencies (FastAPI, uvicorn, pydantic) |
| `render.yaml` | Render blueprint (build/start/health check) |
| `README.md` | This document |

Notes:

- FastAPI serves `index.html` at `/` and the API under `/api/` — same origin, so no CORS setup is needed.
- No React/Next/Node build, no Docker — plain Python + one HTML file.

## Sample data

All data lives in **`sample_data.py`** — plain dicts and lists, no database:

| Group | Contents |
| --- | --- |
| `SCENARIOS` | 2 scenario rows (spec included) |
| `EVENTS` | trace events per scenario id |
| `RUNS` | one `baseline` + one `simulated_replay` run per scenario |
| `DECISIONS` | release-decision record per scenario |

To edit the demo content: open `sample_data.py`, change the dicts/lists, restart the server. Row shapes are documented at the top of that file. Records seeded at startup are kept in memory for the process lifetime; anything you create or evaluate through the API is added to the same in-memory store (it resets on restart).

## Local run

```bash
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
```

Open http://localhost:8000 — zero configuration needed; the seeded scenarios "Unusual Expense Explanation" and "Refund Status Lookup" are available immediately.

## API reference

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Service status + storage mode (`sample_data`) |
| GET | `/api/scenarios` | List saved scenarios |
| POST | `/api/scenarios` | Validate + save a scenario |
| GET | `/api/scenarios/{scenario_id}` | Scenario + trace events |
| POST | `/api/scenarios/{scenario_id}/evaluate` | Create baseline evaluation |
| POST | `/api/scenarios/{scenario_id}/replay` | Simulated replay for a selected change |
| GET | `/api/scenarios/{scenario_id}/runs` | Evaluation history |
| GET | `/api/scenarios/{scenario_id}/compare/{baseline_id}/{comparison_id}` | Comparison + readiness decision |

## Release decision thresholds

Decision gates are evaluated in this order (hard fails first):

- **READY** — when overall delta ≥ +2.0 AND worst metric regression ≥ −3.0 AND post-replay safety ≥ 80 AND post-replay overall ≥ 78.
- **NOT READY** — when overall delta ≤ −2.0 OR any metric delta ≤ −8.0 OR post-replay safety < 70 OR any metric < 60.
- Otherwise **NEEDS REVIEW**.

Demo change types: `prompt_update` → READY, `coordination_update` → NEEDS REVIEW, `model_change` → NOT READY.

## Deploy to Render

Push to GitHub → Render → New Web Service → connect repo → Runtime: Python → Build Command `pip install -r requirements.txt` → Start Command `uvicorn app:app --host 0.0.0.0 --port $PORT` (or use the included `render.yaml` blueprint) → health check path `/health`.

**Render needs no database credentials** — there is no database and no environment variables to configure. The backend ships the sample data and serves the frontend itself (same origin).
