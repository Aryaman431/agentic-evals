Why it matters

Four failures a written suite is built to catch.

A demo that works once is not evidence. These are the four gaps evaluation closes before a release.

One good answer proves only one path.

A single reply shows that one route works. A suite of cases covers the many inputs, tools and edge cases an agent actually takes.

“Sounds right” is not measured right.

Without written expectations — required tools, output fields, thresholds — a passing run is a feeling, not a result you can repeat.

Changes can regress silently.

A prompt or model tweak can lower the pass rate without raising an error anywhere. A gate turns that drop into a failed check.

The final answer hides trajectory errors.

An output can look right while the agent called the wrong tool, skipped a required one, or repeated itself. Trace-aware scorers grade the path too.

How it works

Three steps from test case to CI gate.

Define the expectations once, run them from the CLI or Python, and let the gate decide the release.

Define cases and scorers.

Write test cases with expectations — required tools, output fields, latency and cost budgets — and pick scorers from the built-in registry or add your own.

Run from the CLI or the Python API.

agentic-evals run discovers every eval file and prints a report; Eval(...) and evaluate_suite(...) do the same from code.

Gate the release on thresholds.

evaluate_gate checks pass rate, average score, failed cases, latency and cost against your GateConfig and returns a decision with reasons.

Capabilities

One engine for every kind of check.

Start with a plain input and expected output. Move to traces, tool calls and release gates when you need them — it is the same engine underneath.

Deterministic scoring.

Exact match, substring, regex, JSON Schema, JSON diff, numeric ranges and Levenshtein similarity. No model call required.

Provider-neutral LLM judges.

Ten built-in rubric templates — factuality, closed QA, security, PII leakage and more — graded through your own complete_fn, so any provider works.

Trace-aware scoring.

Score the path, not just the answer: required and forbidden tools, tool arguments, redundant calls, latency, cost and turn count.

Release gates.

GateConfig thresholds on pass rate, average score, failed cases, average latency and total cost. Missing cost data fails the gate instead of passing silently.

Live targets.

Run a suite against a Python callable or an HTTP endpoint. HTTP requests are bounded by the target's timeout.

Eval packs.

Share a suite and the scorer names it needs as one YAML or JSON file. Three packs ship built in.

Quickstart

Your first eval in a few lines.

Install the package, score one suite, then wire the result into CI.

pip install agentic-evals
from agentic_evals import (
    EvalSpan, EvalTrace, EvaluationSample, EvaluatorConfig,
    TestCase, TestSuite, default_registry, evaluate_suite,
)

suite = TestSuite(name="support-answers", version="1", cases=[
    TestCase(id="refund-status", name="Right tool, under budget",
             required_tools=["lookup_refund"], forbidden_tools=["delete_order"],
             max_latency_ms=2000,
             evaluators=[EvaluatorConfig(name="tool_call_precision", threshold=1.0,
                                         config={"allowed_tools": ["lookup_refund"]})]),
])
sample = EvaluationSample(
    case_id="refund-status", output="Your refund is on its way!",
    trace=EvalTrace(trace_id="trace-1", total_latency_ms=350,
                    spans=[EvalSpan(tool_name="lookup_refund")]))
report = evaluate_suite(suite, [sample], registry=default_registry())
print(f"Pass rate: {report.summary.pass_rate:.0%}")

Run agentic-evals run to discover eval files and get an exit code.

Longer variants — a TestSuite with a gate, and an LLM judge — live in the docs.
