# Production Trace → Release Decision

A single-service developer observability console that turns a captured production AI workflow into a reusable test scenario — inspect the production trace, export an AI Ops Spec, run a baseline evaluation, simulate a change via replay, and reach a data-driven release decision.

> **SIMULATED DEMO DATA** — AgenticLens production capture is simulated. The AI Ops Spec is a representative example, not an actual AgenticLens export. Evaluation scores are illustrative, generated by built-in demo logic (no real evaluation framework). Replay is simulated — no real agent application is rerun. Database persistence and API operations are genuinely functional when Supabase is configured.

## What it does

1. **Production Trace** — timeline of a financial-assistant workflow explaining an unusual expense.
2. **AI Ops Spec** — syntax-coloured JSON spec with copy/save.
3. **Baseline Evaluation** — six deterministic metric scorecards + issue list.
4. **Simulated Replay** — choose prompt/model/coordination change, compare vs baseline.
5. **Release Decision** — READY / NOT READY / NEEDS REVIEW from documented thresholds.

## Architecture

Flat single-service layout — no build step, no microservices:

| File | Purpose |
| --- | --- |
| `app.py` | FastAPI app, API endpoints, DB integration, static serving |
| `index.html` | Complete interactive frontend |
| `requirements.txt` | Python dependencies (FastAPI, uvicorn, supabase, dotenv) |
| `schema.sql` | Supabase tables/indexes (run once in the SQL Editor) |
| `.env.example` | Environment variable template |
| `render.yaml` | Render blueprint (build/start/health check) |
| `README.md` | This document |

Notes:

- FastAPI serves `index.html` at `/` and the API under `/api/`.
- Frontend uses same-origin relative URLs — no CORS setup needed.
- No React/Next/Node build, no Docker — plain Python + one HTML file.

## Local setup

```bash
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
```

Open http://localhost:8000 — works with zero configuration in in-memory demo mode with the seeded scenario "Unusual Expense Explanation".

## Supabase configuration

1. Create a Supabase project → SQL Editor → paste and run `schema.sql`.
2. Settings → API → copy the Project URL and `service_role` key.
3. Copy `.env.example` to `.env` and set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
4. Restart the server; `GET /health` will report `"mode": "supabase"`.

**Security:** the service-role key stays server-side only — never exposed in `index.html`, client JavaScript, logs, or committed (`.env` is gitignored).

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Service status + database connectivity/mode |
| GET | `/api/scenarios` | List saved scenarios |
| POST | `/api/scenarios` | Validate + save a scenario |
| GET | `/api/scenarios/{scenario_id}` | Scenario + trace events |
| POST | `/api/scenarios/{scenario_id}/evaluate` | Create baseline evaluation |
| POST | `/api/scenarios/{scenario_id}/replay` | Simulated replay for a selected change |
| GET | `/api/scenarios/{scenario_id}/runs` | Evaluation history |
| GET | `/api/scenarios/{scenario_id}/compare/{baseline_id}/{comparison_id}` | Comparison + readiness decision |

## Release decision thresholds

Decision gates are evaluated in this order (hard fails first):

- **READY** — when overall delta ≥ +2.0 AND worst metric regression ≥ −3.0 AND post-replay safety ≥ 80 AND post-replay overall ≥ 78.
- **NOT READY** — when overall delta ≤ −2.0 OR any metric delta ≤ −8.0 OR post-replay safety < 70 OR any metric < 60.
- Otherwise **NEEDS REVIEW**.

Demo change types: `prompt_update` → READY, `coordination_update` → NEEDS REVIEW, `model_change` → NOT READY.

## Deploy to Render

Push to GitHub → Render → New Web Service → connect repo → Runtime: Python → Build Command `pip install -r requirements.txt` → Start Command `uvicorn app:app --host 0.0.0.0 --port $PORT` (or use the included `render.yaml` blueprint) → add env vars `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` → health check path `/health`.
