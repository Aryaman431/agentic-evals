Quickstart · Suites

Declarative suites with a release gate.

Expectations cover tool calls, output fields, JSON Schema, latency and cost. Run the suite against a live target, then gate the release on the report.

from agentic_evals import (
    GateConfig, PythonTarget, TestCase, TestSuite,
    evaluate_gate, run_live_suite,
)

suite = TestSuite(
    name="refunds",
    version="3",
    cases=[
        TestCase(
            id="refund-status",
            name="Looks up the order before answering",
            input={"message": "Where is my refund for ORD-1042?"},
            required_tools=["lookup_order"],
            forbidden_tools=["issue_refund"],
            required_output_fields=["status"],
            max_latency_ms=2000,
            max_cost_usd=0.02,
            tags=["refunds"],
        ),
    ],
)

report = run_live_suite(suite, PythonTarget(callable_path="my_app:run_case"))
print(f"{report.summary.passed_cases}/{report.summary.total_cases} cases passed")

decision = evaluate_gate(report, GateConfig(
    min_pass_rate=0.95,
    max_failed_cases=0,
    max_average_latency_ms=1500,
    max_total_cost_usd=0.25,
))
if not decision.passed:
    raise SystemExit(f"Release gate failed: {decision.reasons}")

The gate returns a decision plus the reasons it failed, so CI can print exactly what went over budget.

Quickstart · Judges

Bringing your own LLM judge.

The package never calls a model itself. Pass a complete_fn and mix rubric judges with deterministic and trajectory scorers on the same case.

from agentic_evals import (
    FACTUALITY, SECURITY, EvaluatorConfig, LLMRubricEvaluator,
    TestCase, default_registry, evaluate_suite,
)
from my_app.llm import complete  # (prompt: str) -> str

registry = default_registry()
registry.register(LLMRubricEvaluator("factuality", FACTUALITY, complete_fn=complete))
registry.register(LLMRubricEvaluator("security", SECURITY, complete_fn=complete))

case = TestCase(
    id="policy-answer",
    name="Answers from the policy without leaking internals",
    evaluators=[
        EvaluatorConfig(name="factuality", threshold=0.8),
        EvaluatorConfig(name="security", threshold=0.9),
        EvaluatorConfig(name="tool_call_recall", threshold=1.0),
    ],
)

# suite and samples come from your own eval data
report = evaluate_suite(suite, samples, registry=registry)

Any provider works, as long as it can turn a prompt into text.

Capability notes

Details behind each capability.

What the code actually does, written from the source rather than the pitch.

01

What the judge records per score.

LLMRubricEvaluator takes your complete_fn: (prompt) -> str and grades with a RubricTemplate — ten are built in, from factuality to SQL correctness. Each score records the rubric name, the parsed verdict and the raw completion in Score.metadata. There are no built-in retries, repeated sampling or agreement metrics: if you need retry-and-vote, wrap it in your own complete_fn where you can see the logic.

02

Every gate threshold.

GateConfig sets min_pass_rate, min_average_score, max_failed_cases, max_average_latency_ms and max_total_cost_usd. evaluate_gate compares them against the report summary and returns a GateDecision with passed, reasons and the observed values. If a cost limit is set but cost data is missing or incomplete, the gate fails with “Total cost is unavailable or incomplete.” instead of passing.

03

Live targets and their timeouts.

PythonTarget resolves a trusted module:function and calls it once per case. HTTPTarget POSTs JSON {input, case_id} to a URL. Both carry timeout_seconds (default 30), and the HTTP request uses it as its socket timeout. Live targets execute trusted code by design — only point them at suites and targets you trust.

04

Eval packs on disk.

An EvalPack is a TestSuite plus the scorer names it needs, stored as YAML or JSON. load_pack fails fast when a required scorer is missing from the registry. Three packs ship built in: factual-qa, json-output-contract and tool-use-correctness.

05

How the CLI finds eval files.

agentic-evals run looks for *_eval.py, eval_*.py and *.eval.py, imports each file, and exits 1 if any Eval(...) case failed — 0 when everything passes. No config file and no project setup needed.
